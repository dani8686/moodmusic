# امنیت، کلید امضا و تاریخچه مخزن (فارسی)

## آنچه بررسی شد

فایل ZIP قدیمی مخزن (`mood-source (1).zip`) حاوی دو مورد حساس بود:

1. `signing.p12` — یک keystore خصوصی واقعی (RSA 2048، alias `moodmusic`).
2. `app/build.gradle.kts` حاوی رمز هاردکد\u200cشدهٔ `moodmusic-fixed-password` برای همان keystore.

چون مخزن **عمومی** است، هر کسی که این ZIP را دانلود کند هم کلید خصوصی و هم رمز را دارد و می\u200cتواند APK مخربی با همان امضا بسازد. این یک افشای واقعی اعتبارنامه است.

## اقدامات انجام\u200cشده در این شاخه

- ZIP حاوی کلید از **درخت فعلی مخزن حذف شد**؛ سورس به\u200cصورت فایل\u200cهای معمولی استخراج و یکپارچه شد.
- `signing.p12` هرگز به فایل\u200cهای جدید کپی نشد.
- رمز هاردکد\u200cشده حذف شد. `app/build.gradle.kts` اکنون فقط از **متغیرهای محیطی** می\u200cخواند:
  `MOOD_STORE_FILE`، `MOOD_STORE_PASSWORD`، `MOOD_KEY_ALIAS`، `MOOD_KEY_PASSWORD`.
- `.gitignore` شامل `*.p12`, `*.jks`, `*.keystore`, `*.apk` است.
- مانیفست هیچ `INTERNET`، `WRITE_EXTERNAL_STORAGE` یا `MANAGE_EXTERNAL_STORAGE` درخواست نمی\u200cکند. خروجی فایل از طریق SAF انجام می\u200cشود.
- workflow جدید، کلید را **خارج از checkout** (در `runner.temp`) نگه می\u200cدارد و ترجیحاً از GitHub Actions Secrets می\u200cخواند.

## محدودیت مهم (صداقت امنیتی)

**صرفاً حذف فایل از آخرین کامیت، افشا را جبران نمی\u200cکند.** کامیت\u200cهای قبلی `main` همچنان ZIP حاوی کلید و رمز را در تاریخچهٔ عمومی دارند. بازنویسی تاریخچهٔ یک مخزن عمومی عملیات مخربی است و طبق دستور بدون اجازهٔ صریح انجام نشد.

اقدامات لازم توسط صاحب مخزن:

1. **چرخش کلید (Key rotation):** کلید قدیمی را کنار بگذارید. APK نسخه ۲ با کلید جدیدی امضا می\u200cشود. نتیجه: نصب\u200cهای قدیمی که با کلید لو\u200cرفته امضا شده\u200cاند را نمی\u200cتوان به\u200cصورت به\u200cروزرسانی روی آن\u200cها نصب کرد؛ باید نسخهٔ قدیمی حذف (Uninstall) شود. اطلاعات کاربر (کتابخانه، پلی\u200cلیست\u200cها) با `allowBackup=false` و عدم پشتیبان\u200cگیری ابری قبل از حذف از بین می\u200cرود؛ پیشنهاد می\u200cشود قبل از حذف، خروجی ZIP از دسته\u200cها گرفته شود.
2. در `Settings → Secrets and variables → Actions` چهار Secret بسازید:
   - `MOOD_KEYSTORE_BASE64` = خروجی `base64 -w0 release.p12`
   - `MOOD_STORE_PASSWORD`
   - `MOOD_KEY_ALIAS` (پیش\u200cفرض `moodmusic`)
   - `MOOD_KEY_PASSWORD`
3. اگر Secretها تنظیم نشوند (token این نشست اجازهٔ ساخت Secret نداشت: پاسخ 403 `Resource not accessible by integration`)، workflow یک کلید تازه با `keytool` روی runner می\u200cسازد و آن را در **Actions cache خصوصی شاخه** نگه می\u200cدارد تا بیلدهای مکرر همان شاخه امضای یکسانی داشته باشند. این جایگزین امنِ Secrets نیست، ولی کلید هرگز وارد Git نمی\u200cشود.
4. برای پاک\u200cسازی کامل تاریخچه، در صورت تمایل و با **اجازهٔ صریح** می\u200cتوان از `git filter-repo` استفاده کرد؛ سپس باید به تمام همکاران اطلاع داده شود که تاریخچه تغییر کرده است. مخزن همچنان عمومی می\u200cماند.

## توصیهٔ عملی

برای انتشار واقعی، حتماً Secretها را به\u200cصورت دستی تنظیم کنید تا کلید ثابت و خصوصی بماند و نسخه\u200cهای بعدی قابل به\u200cروزرسانی باشند. کلید قدیمی را هر جای دیگری (پشتیبان\u200cها، پیام\u200cها، لاگ\u200cها) باطل کنید.
