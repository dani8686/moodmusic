# Mood Music Sorter V3 — architecture, privacy and verification

Status: **PARTIAL** overall. CI run [43035039717](https://github.com/dani8686/moodmusic/actions/runs/43035039717) passed 20 tests, lint, Debug/Release, migration coverage and APK package/signature/permission checks. Physical-device and live-provider behavior are not proven by CI.

## Data compatibility

The application ID remains `com.daniel.mood`. Room schema 3 adds intelligence tables and provenance/feedback columns through `MIGRATION_2_3`; existing songs, manual corrections, playlists and settings are not recreated. `DatabaseTest` creates a real schema-2 SQLite database and validates migration. Preference storage and export code from V2 remain in place.

Listening history starts with V3 events; earlier listening cannot be reconstructed. History export is real CSV through SAF. History, learned DNA and online caches have separate deletion controls. History retention is configurable (30/90/365 days/forever).

## Local intelligence

- **Music DNA:** exponentially weighted listening time, completion, early skips, likes/dislikes, mood/BPM/energy/vocal acoustic features. No filename or metadata classification.
- **Radar:** explainable acoustic/mood/tempo/taste matching, recency exclusions, dislike filtering and cached recommendations.
- **Mood Journey:** constrained mood/energy paths, familiarity controls, song replacement, saved journeys and replay.
- **Smart DJ:** Media3 two-player overlapping crossfade. Fade duration is quantized using measured BPM when available. The source is a heuristic transition engine, not beat-aligned stem mixing; no claim of perfect beat synchronization or loudness normalization is made without device tests.
- **Music Twin:** controlled English/Persian commands map to whitelisted actions. Online interpretation can only select the same action schema. Destructive DNA/history deletion requires confirmation. Unknown commands do not execute arbitrary code or external actions.
- **Time Machine:** real V3 listening events, calendar/month comparisons, on-this-day, top tracks/artists/moods, historical playlists and CSV export.

## Online modes

**Offline** is the default and retains local classification and intelligence. **Hybrid** is recommended: local analysis remains available and online analysis is optional. **Online AI** requests online classification with local fallback on errors.

Every audio upload requires explicit consent. Network policy includes Wi-Fi-only, file-size and daily-request limits, retries/backoff, local fallback, provider status and processing logs. Audio is read through the app content resolver and sent as inline audio only when configured. No provider key is embedded in source or resources.

### Provider choices and official sources

- **Gemini audio analysis / optional Twin interpretation:** Gemini accepts real inline audio, so audio analysis is not simulated with a text prompt. [Audio documentation](https://ai.google.dev/gemini-api/docs/audio) states a 20 MB inline-request ceiling and audio downsampling/mixing behavior. Default request limit in the app is lower (15 MB) and configurable.
- [API-key security](https://ai.google.dev/gemini-api/docs/api-key): Google says not to expose production keys client-side or hardcode them in mobile apps; a backend proxy is recommended. Personal advanced keys are encrypted using Android Keystore, but this does **not** make a distributed client key equivalent to a secure backend. Production/shared deployment must use a user-supplied HTTPS backend with authentication, authorization, rate limits, secret storage, logging/redaction and abuse controls. No hosted backend is included.
- [Pricing/billing](https://ai.google.dev/gemini-api/docs/pricing) and [privacy terms](https://ai.google.dev/gemini-api/docs/billing): free-tier inputs may be used to improve Google products; quotas, availability and pricing can change. The app never promises permanent free access. Users must check current official pricing and regional availability.
- [Interactions retention](https://ai.google.dev/gemini-api/docs/interactions-overview) and [zero data retention](https://ai.google.dev/gemini-api/docs/zdr): request retention/abuse logging and guaranteed-ZDR conditions differ by product/tier. This app does not claim zero retention. Inline audio avoids using the File API.
- **Apple iTunes Search/Lookup:** keyless catalog links and metadata, not downloads or streaming rights. Search terms are transmitted. Current quota and redistribution terms remain **PARTIAL** and must be reviewed before commercial/redistributive use: [Apple Search API resources](https://performance-partners.apple.com/search-api).
- **LRCLIB:** optional keyless lyrics. [Official API notes](https://lrclib.net/llms.txt) require a User-Agent and rate-limit compliance; title/artist/duration queries are transmitted. Availability and content rights are not guaranteed.

The provider interfaces for audio, catalog/discovery, lyrics and conversation are replaceable. Only HTTPS URLs are accepted for a custom backend.

## Signing

Production signing is **BLOCKED** until a new private keystore is supplied through `MOOD_KEYSTORE_BASE64`, `MOOD_KEYSTORE_PASSWORD`, `MOOD_KEY_ALIAS` and `MOOD_KEY_PASSWORD`. The historical public key is compromised; Git history is intentionally not rewritten. Without secrets CI produces a clearly labelled debug-signed TEST release, never a production update.
